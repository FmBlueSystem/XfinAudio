# AI-guided playlist improvement

## Objective and problem
Enable a user to tell optional AI how to improve an existing playlist and inspect concrete proposed track replacements/order before any local edit or save. The previous Prep AI busy-state fix preserves text but cannot satisfy this outcome: Prep supplies generation parameters, Review only narrates, and Editor translates four limited operations.

## Scope and authorization
The user chose concrete track/ordering proposals over translating requests into existing limited operations, then authorized local implementation. Work on isolated `feat/ai-playlist-improvement` rooted at the clean `fix/prep-ai-readiness` commit `ba58326`; do not touch the running combined preview, main checkout, installed app, existing app/library data, audio, or Serato V2. No real AI/provider calls, credential inspection, network access, real-library scans, push, PR, merge, or app replacement. Fixtures and mocked transports only. Each real request must remain opt-in with a precise payload preview and native confirmation; local preview and explicit save remain separate. Provider output is untrusted and id-only; reject unknown ids, duplicates, unsupported changes, stale revisions, and unsafe replacements before proposing any edit.

## Acceptance and checks
- From a playlist editor, a user can type an improvement instruction and see the exact playlist metadata slated for disclosure before explicit authorization. No title/path/credential/audio disclosure without that request-specific consent. The provider receives only bounded authorized metadata (no filesystem paths or raw audio).
- The provider receives only request-scoped random tokens, never stable path-derived ids; a bounded model response may reference only tokens in the authorized candidate set (at most 80 draft + 20 replacements). Malformed, stale or out-of-scope responses produce no edit.
- The resulting ordered before/after diff and assessment appear as a local preview; applying it changes only a draft. Replacements require a dedicated proposal-bound, exact-order save with CAS; the ordinary manual save must keep rejecting additions. No automatic request, apply or save.
- Strict TDD from repository AGENTS.md: observe RED, GREEN, REFACTOR on behavior changes. Focused Python/Node tests, then `uv run python scripts/release_gate_check.py --run` and `cd desktop-electron && npm test` as applicable; never override coverage floor.
