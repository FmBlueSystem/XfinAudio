# Design

Main owns folder selection and registers the canonical destination with the backend via a main-only command. Preload exposes chooseSeratoDestination, previewSeratoExport, commitSeratoExport and receipt-only reveal methods; confirmed publication is noncancellable. Renderer supplies source identities and a bounded name, never paths, readiness, bytes or serialized recommendations.

Backend reuses the existing Serato plan/byte/write/validation seams without importing desktop or calling auto-discovery. Fresh saved-set assessment scores exact order; output plans retain source-volume semantics. Server-held preview tokens bind all commit inputs and are consumed/idempotent. Destination ancestors/leaf targets and source identities are checked before publication. Backup/readback behavior is retained. Direct selected Serato destination is the product workflow; private staging is only an implementation safeguard.

Renderer error normalization extracts safe machine codes but displays mapped Spanish text; local logs retain technical details. A source archive helper validates its complete member list and rejects unexpected symlinks.


Anchored overwrite uses capture/verify/no-replace publication, with a brief target-name gap and prior backup retained. It never overwrites a concurrent arrival; recovery copies remain if restoration conflicts. Native exclusive rename is exercised on Linux, and the Darwin signature/flags have mocked tests pending native execution. Normal close drainage waits for active publication before the bridge's bounded termination policy.

The new export path accepts at most 500 track references and caps generated/existing crate IO at 16 MiB. The legacy unanchored writer retains its prior size behavior. All new byte reads are bounded before allocation; oversized requests fail without truncation or writes.
