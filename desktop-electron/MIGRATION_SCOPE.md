# Qt-free migration scope

The new application uses Electron's sandboxed local renderer and the existing Python engines through a bounded local subprocess protocol. The frozen runtime must contain no Qt. The original Qt source and installation are retained for rollback; they are not the new runtime.

## Restored functional workflows

- Authorized, read-only metadata scan/rescan; library observation; ordinary search/completeness views and provider-free structured filters, sorting and duplicate hiding
- All eleven original strategies and safe/balanced/adventurous variants; real read-only spectral, danceability and edge-profile completion and version/current-file cache handling; original cohesion policy
- Deterministic generated-review transitions, readiness/engine evidence, replacement comparison and constraint-aware reorder/remove/backfill; source/policy-bound review and cached-variant selection
- Save/reopen, rename, duplicate and explicit saved-set editing; local saved search/compare; native-confirmed exact-revision removal with retained recoverable app-owned records
- Persistent local Prep locks/exclusions/genre, ordinary preferences and dirty-close handling, with unavailable references disclosed
- Manual Live guidance using the original ranking/history helpers; original-file preview playback with opaque identities
- Metadata gaps, repair guidance and exact filtered worklist export to Serato
- Serato-only direct export to an explicitly selected folder, immutable preview, native confirmation, validated publication and replacement backups
- Original loudness measurement/tag writer behind an exact scope preview and separate native confirmation; original-byte backups and truthful partial outcomes
- Optional original language interpreters/narrators for eight surfaces, with fixed recipient, per-request consent/native confirmation, selected credential-file identity, bounded original timeouts and local authority over Apply
- Explicit native-selected legacy app-data import into a fresh destination, with read-only source snapshots, retained backups/recovery and separate music-root reauthorization

A feature's focused automated evidence is documented in its `openspec/changes/` report. Whole-source gates, the native fixture matrix, and frozen-runtime verification are distinct checks; the final candidate's matching evidence is authoritative.

## Deliberate boundaries

- Other DJ export formats and CSV/JSON report exports are outside this replacement scope. Serato database V2 is never written
- Scanning/profile completion do not rewrite audio or infer missing BPM/key/energy tags. Only a separately reviewed/confirmed loudness run may write its documented tags/comments
- Optional assistance never becomes a substitute for the local musical engine. Current Prep requests do not share a full-library title list, and AI Library proposals are read-only before Apply; local Library filters remain editable without AI
- When global locked-repair priority is unavailable, Metadata assistance omits that fact rather than claiming a zero count
- Legacy import is fresh-profile-only, not an automatic merge into an already used destination. Credentials, old root permissions, provider enablement and automatic-write settings are not imported. Only explicitly listed safe preferences are carried over. Source files stay unchanged
- Ancillary original presentation/convenience features such as language selection, global undo/redo, help/tour menus and empty saved-set creation are not promised as identical. The new UI is Spanish
- Work is bounded and serialized where required for source/commit safety. Cancellation stops pending work; it cannot undo a completed file write or recall data already sent

## Acceptance boundaries

- Automated provider tests use newly created dummy credentials and injected fake transport with network blocks. They do not establish actual provider access, latency or reliability
- Controlled native dialogs, muted playback, generated synthetic audio and temporary Serato folders do not establish human/audible acceptance, live Serato import or long-library stress behavior
- Linux packaging targets the explicitly tested Debian13 x86_64/glibc2.41 baseline and still requires an ordinary graphical/audio session and Chromium sandbox support. Source-mode macOS checks do not constitute a macOS bundled/signing result
- Never disable Electron's sandbox to force startup. The final report must distinguish a frozen-core smoke from an actual graphical launch and disclose any verified host blocker
- No automatic updater, public release, signing, installed-application replacement or silent migration of real user data is part of these development validations
